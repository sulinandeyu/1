## 本阶段代码修复与可观察证据

1. `PhotoAnalyzer` 输出 `recognized / uncertain / failed / notEvaluated`，保留最高置信度、标签数量和失败原因。
2. `SkySegmentationService` 输出显式成功或失败原因；模型输入改为保持长宽比并记录有效内容区域，语义输出裁掉 letterbox 后再生成蒙版。
3. 分割状态区分 `available / noUsableRegion / failed / notEvaluated`，记录天空、地面、植被、水面和建筑覆盖率。
4. `PhotographyDecisionEngine` 在识别失败时移除语义 HSL 假设并限制风格强度；识别不确定时限制风格强度；分割失败时关闭伪局部天空参数，保留问题驱动的全局曲线与亮度区域处理。
5. `LocalAdjustmentProcessor` 只把覆盖率 0.4%...86% 的蒙版视为可用，输出每个区域“已执行/跳过及原因”回执。植被、水面、建筑、道路的强度改为受实际阴影余量、饱和度和噪声风险约束的自适应值。
6. 人物照片若检测到人脸但没有可靠整人物蒙版，语义区域和天空局部调整继续安全跳过；如有整人物蒙版，天空会扣除人物区域。没有加入磨皮、美白、瘦脸、面部修复或生成式处理。
7. `QualityCheckService` 不再让 JPEG 广泛微差单独绕过“效果不足”；并检查预期场景区域是否有真实执行回执、蒙版边界是否出现异常亮度跳变、人物区域亮度/颜色/纹理是否相对背景被过度改变。
8. App 日志和诊断面板现在显示识别状态、置信度、失败/降级原因、五类蒙版覆盖率与真实区域执行回执。

## 可重复的 macOS/iPhone 验收步骤

1. 在 macOS 用当前工作区构建并安装 App；不要更换上述输入文件。
2. 通过现有“样片复测/相册导入”入口逐张导入素材，等待流水线完成；处理失败必须保留错误，不得把原图作为成功成片。
3. 在诊断面板逐项抄录：场景状态、最高置信度、标签、分割状态/原因、五类覆盖率、最终配方、区域执行回执、质量问题、RGB MAE、变化像素比例和输出尺寸。
4. 分别保存原图和 AI 成片，记录实际文件名与 SHA-256；重新读取导出的 JPEG，确认尺寸、方向和本次照片对应关系。
5. 对室内图检查灯具高光、混合光和墙面中性色；对夜景检查灯源裁切、死黑、噪声和建筑层次；对人物图检查脸部结构、肤色、纹理和背景相对变化。
6. 若日志显示 `failed`、`uncertain`、`noUsableRegion` 或某区域“跳过”，验收报告必须保留该状态，不能改写为场景化局部精修成功。
7. 补充一张天空/风景和一张植被/道路手机原图后，以同一流程补跑缺失场景。

## 通过条件

- 三张现有照片都生成可重新读取的新 JPEG，且没有输出/缓存串图。
- 识别、决策、区域回执与实际像素区域相符；预期局部处理没有执行时质量门明确失败或记录降级，而不是宣称成功。
- 高光、阴影、色偏、饱和度、噪声、锐化和局部边界指标不触发失败门。
- 人物图不触发人物相对亮度/颜色或纹理异常；人工放大检查没有脸型、五官、皮肤纹理变化。
- 天空与植被场景在补充真实素材并完成相同记录前，Phase 2 不能宣称五场景端到端全部通过。
