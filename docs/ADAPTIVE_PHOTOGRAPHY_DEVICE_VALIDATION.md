# 自适应摄影引擎真机验收步骤

## 发布前门禁

1. 在得到用户明确确认后再提交并推送当前修改。
2. 等待 GitHub Actions `iOS Build` 完成 Swift 测试与 iOS Simulator build。
3. 构建成功后，仍需再次获得发布确认，再手动运行 `TestFlight Release`。
4. 记录 Git 提交、TestFlight build、iPhone 型号和 iOS 版本。

## 样片要求

至少使用以下原始文件；不得通过微信二次压缩：

- 曝光正常、曝光不足和曝光过度的相近画面。
- 同一地点的暖光、冷光或混合光照片。
- 高光强、阴影深、低反差和高噪声照片。
- 天空/风景、植被/道路、室内、城市夜景、人物各至少两张。

## 每张照片必须保存

- 原图与 AI 成片原始文件。
- 完整诊断页截图。
- 逐图摄影目标、参数证据和每项状态。
- 候选数量、每个候选的目标达成度、问题改善、区域影响与最终选择原因。
- 场景/分割状态、蒙版覆盖率、局部执行或跳过原因。
- 总处理耗时、内存、质量问题和是否发生一次修正。

## 通过标准

- 相同像素测量但场景标签不同，不应产生不同技术配方。
- 同场景的欠曝、过曝、偏暖、偏冷、低反差、高噪声输入必须得到方向正确且幅度不同的参数。
- 最终完整分辨率配方与低分辨率选中的配方一致。
- AI 成片不是原图、缓存旧图或静默回退，但也不能仅凭像素不同判定合格。
- 高光、暗部、色彩、噪声、锐化和局部边界不能新增明显损伤。
- 人物五官、脸型、体型、皮肤纹理和真实身份保持不变，肤色不能明显偏橙、红、黄或绿。

## 回传材料

每组请提供原图、AI 成片、完整诊断截图，以及一句主观评价（更好 / 原图更好 / 都不好和原因）。只有这些材料齐全后，才能确认 iPhone 端摄影效果，而不是只确认代码或构建成功。
