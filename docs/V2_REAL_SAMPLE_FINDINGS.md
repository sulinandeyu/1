# MasterCamera V2 真实样片首轮结论

日期：2026-10-21

## 输入材料限制

本轮收到的 4 个文件是 iPhone 上的“原图 / AI 成片”对比界面截图，并不是相机写出的原始 JPEG/HEIC 与最终成片文件。因此可以判断 UI 中的视觉差异和旋转现象，但不能从这些截图可靠读取原始拍摄 EXIF、镜头信息、原始色彩空间，也不能把截图上的像素差异当作原始照片的最终画质验收。

4 张截图均为 1179×2556，截图本身没有可用于追查拍摄方向的 EXIF Orientation。

## 首轮观察

- 客厅组：AI 成片与原图在截图可见区域的差异非常弱，采样估算 RGB / 亮度平均绝对差异约为 1%。
- 电脑桌组：差异比客厅组明显，但仍主要集中在轻微明暗和色彩变化，截图采样估算约为 5%。
- 两组照片在应用中都横向旋转，说明方向问题不是单一场景偶发现象。
- 比较界面的原图与成片切换确实读取不同属性；工程中没有发现把两个按钮都直接绑定到 `originalImageData` 的错误。

## 已定位原因

1. 捕获照片前没有给 `AVCapturePhotoOutput` 的视频连接写入设备当前的 horizon-level rotation angle。后续分析和渲染只能遵守已有 EXIF，无法修复捕获时错误或缺失的方向。
2. 原版本虽执行了处理链，但室内通用配方参数过于克制，缺乏室内/桌面独立曲线、黑位和材质局部对比，因而客厅样片出现“算法执行了但肉眼几乎看不出”的结果。
3. 原版本没有真实文件标识、统一解码后的像素差异、直方图、逐阶段图像，无法快速判断效果弱是发生在决策、滤镜执行、最终渲染还是展示阶段。

## V2 复测方法

V2 在相机页加入“样片复测”：从系统照片库选择未经截图的原始 JPEG/HEIC，应用会走与拍照相同的完整处理链。信息面板可查看文件标识、方向、尺寸、色彩空间、RGB/亮度/颜色差异、亮度直方图、执行模块和逐阶段像素预览。

真机验收仍需要用户用原始文件重新导入或重新拍摄。截图只能作为问题证据，不能作为最终画质通过证据。
