## 新增或更新的测试意图

1. 同一场景标签、不同曝光输入必须产生方向相反的曝光决策。
2. 同一室内标签、不同真实色偏必须产生方向相反的白平衡修正。
3. 候选不能统一缩放白平衡和 HSL。
4. 同一地面区域统计在不同全图亮度关系中必须得到不同局部曝光目标。
5. 主体识别失败、无效蒙版、识别失败和分割失败必须进入可审计安全降级。
6. 既有人物保护、区域问题、候选选择和问题改善评分测试继续保留。

## 真实照片回归基线

已重新运行 `scripts/Analyze-V82FourScenes.ps1`，结果写入 `TestPhotos/V8_2_FourScenes/v8_1_pair_metrics.json`。该脚本只量化用户确认来源的原图与 V8.1 成片，不生成 V9 成片，也不替代 iOS 验收。数据再次确认：

- 自拍面部平均饱和度由 19.08 增至 24.88，存在人物颜色过强风险；
- 阴天建筑天空平均亮度由 212.44 降至 192.98，天空饱和度由 5.78 增至 15.52；
- 人物与白车场景天空平均亮度由 229.84 降至 195.99；
- 树木场景阴天天空平均亮度由 191.17 降至 167.05。

这些问题直接对应 V9 的无确认色偏不改白平衡、阴天不自动增蓝、天空目标由区域实测求值，以及 V8.2 的肤色/中性色源图相对保护。

柿子 Build 22 配对也已用 `scripts/Analyze-V8PersimmonPair.ps1` 重算，结果位于 `TestPhotos/V8_Persimmon/paired_metrics.json`。冠层亮度只由 86.86 增至 90.10、饱和度只由 8.06 增至 8.68，而阴天天空亮度由 182.91 降至 171.22、饱和度由 6.69 增至 9.07。这支持已确认的根因：主体改善不足，同时背景天空发生了并非主体目标的色调变化。V9 因而用可靠主体相对全图的亮度差计算主体分离，并禁止阴天标签直接制造蓝色。

## 真机验收时必须保存

每个场景保存原图、AI 成片、差异页和完整诊断页。至少覆盖：

1. 同一户外场景的一张偏暗照片和一张偏亮照片；
2. 阴天建筑或阴天天空；
3. 柿子树或其他主体明确的植被照片；
4. 室内混合光；
5. 夜景；
6. 近景人物和环境人物。

重点核对诊断中的“逐图参数证据”、候选理由、局部执行回执、最终区域变化、肤色保护和中性色保护。若结果仍过弱，应先确认选中的候选是否解决了已检测问题；若渲染前参数明显而成片无变化，再检查 Core Image 全分辨率与保存链路，不继续盲目增加参数。
