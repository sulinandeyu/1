## 2. 案例 A：山谷风光

### 原图问题

- 整体亮度和中间调偏低，山体与道路的空间层次不够清楚。
- 天空具有真实云层，但亮度与蓝色关系较平，不能靠统一加蓝解决。
- 植被颜色分离弱，远景受雾气影响；若简单增加清晰度，会同时放大雾边和局部光晕。
- 没有单一人物主体，画面依赖道路引导、山体层次、天空与光束共同建立视觉重心。

### 摄影师处理思路

- 在保护太阳和云层形态的前提下增加中间调可读性。
- 通过前景道路、中景植被、远景山体之间的局部反差建立空间，而不是全图统一 HDR。
- 让天空与地面形成协调的冷暖/明暗关系；蓝天、绿色和暖光服务于光照氛围。
- 成片颜色和光束非常强烈，属于可供理解目标方向的风格样例，不应被当作自然度合格线。

### 可转化开发依据

- `PT-AESTHETIC-001`：无可靠单一主体时，依据道路、空间区域和亮度层次生成全图视觉层级目标。
- `PT-AESTHETIC-002`：天空、植被、地面分别测量色相/饱和度/亮度，再求解区域之间关系；禁止直接复制成片 RGB 或 HSL。
- `PT-AESTHETIC-003`：真实云层、太阳、高光形态和雾气属于氛围保护项，增强幅度受高光剪切、噪声和蒙版边缘约束。

### 当前实现差距

- 现有模型能分割天空、植被、地面和建筑，但此前没有输出更完整的结构化视觉理解。
- 当前局部渲染能执行，但摄影目标主要是技术校正；缺少“前/中/远景共同服务画面”的明确规划记录。
- Windows 无法验证 Core Image 真正成片，必须在 C 诊断路径的 iPhone 输出中检查云层光晕、绿色荧光和道路边缘。

## 3. 案例 B：地铁环境人像

### 原图问题

- 原片整体偏暗，人物与环境的亮度关系不足，黑色服装和车厢暗部细节压缩。
- 环境具有绿色/冷色人工照明，人物肤色相对偏暖；完全中和环境色会破坏现场氛围。
- 直接抬高全图阴影会让黑位发灰、车厢失去纵深，并可能放大暗部噪声。
- 直接套青橙滤镜会污染肤色和白色灯带。

### 摄影师处理思路

- 先恢复可恢复阴影与中间调，而不是移动已剪切端点。
- 使用曲线建立黑位、暗部、中间调和亮部的关系；不同截图反映的是意图，不是可迁移的曲线坐标。
- 保留绿色/冷色环境，同时让人物维持自然暖色参与感，利用主体和背景的冷暖、亮度关系形成层次。
- 教程中的阴影、中间调、高光色彩分级以及多个滤镜比例，是该照片的操作记录；不能转成“地铁统一绿色”规则。
- 胶片颗粒、褪色和滤镜叠加属于可选质感，必须在噪声、人物皮肤和画质允许时才考虑。

### 可转化开发依据

- 先测量人物/背景亮度差、混合光、可靠中性色、人物蒙版及暗部噪声，再确定主体曝光和环境色保留目标。
- 人物肤色保持相对原图：禁止通过全局调色把面部推向橙红、青绿或灰黄。
- 冷暖分离只在同时具备混合光、高亮源和可靠人物/主体证据时以小幅度启用；证据不足为 0。
- 人物蒙版只参与保护和整体摄影级光影关系，不执行磨皮、祛痘、瘦脸、五官/体型改变或生成式重建。

### 当前实现差距与本阶段落实

- 差距：此前 C 方案有参考目标和动态参数，但没有独立的 `AestheticPhotographyPlanner`；色彩分级只根据全图通道差，无法解释主体/环境关系。
- 落实：新增结构化 `VisualSceneUnderstandingResult`，记录主体置信度、类级语义区域、光源证据、色彩关系、保护项和未知项。
- 落实：新增 C 路径专用 `AestheticPhotographyPlanner`，只根据当前照片残差生成主体/背景、局部反差、颜色分离和风险目标，并把结果传入现有动态求解器。
- 仍未验证：实际 iPhone 肤色偏移、人物蒙版边缘、绿色环境自然度及盲测偏好。

## 4. 案例 C：车内视频帧

两张截图不是同一帧，人物姿态、时间、窗外和车内光线均不同，不能作为参数前后对照。它们只说明车内场景可能同时存在：窗外强光、车顶暖色反射、人物肤色、深色衣物和快速变化的曝光。可借鉴原则是：

- 把车窗/强光和人物分别测量，避免全局提亮导致窗外溢出。
- 在没有可靠中性色时保留现场光，不用全图 RGB 均值猜白平衡。
- 视觉理解置信度不足时记录未知，退回亮度蒙版和全图协调，不编造人物光位或环境语义。

## 6. 禁止性结论

本目录不能证明任何参数在所有照片上有效，也不能证明小苏相机已经达到教程成片的审美水平。教程截图只支持提炼“为什么调整”和“需要测量什么”。所有实际参数仍必须由当前用户照片的曝光、颜色、主体关系、可靠蒙版、噪声和保护边界动态求解，并经过 Core Image 真机渲染及人工偏好测试。
