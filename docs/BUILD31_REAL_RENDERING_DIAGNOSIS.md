## M / R3-I 技术失败定位

- 地面：平均亮度 0.2002，5% 分位 0.0025，黑位 32.56%，阴影 54.23%，中性色亮度 0.3078。
- 建筑：平均亮度 0.2788，黑位 32.35%，阴影 39.03%，中性色亮度 0.0291。
- 实际参数把全局约 -0.56 EV 与全亮度范围地面 -1 EV 叠加；区域缺少足够的暗部端点保护与羽化。
- 因此 `tooHarsh`、`neutralLuminanceLoss`、`localMaskBoundaryArtifact` 是实际像素失败，不是质检误报，禁止放宽阈值。

## D 过弱的根因与修复链路

1. Build 31 的 D 虽有可靠区域蒙版（植被约 42.3%、地面约 32.8%、天空约 10.4%、建筑约 1.5%），但局部参数接近中性：地面约 -0.037 EV、植被约 -0.010 EV、黄色 HSL 仅约 +0.037。
2. 高反差照片的目标反差此前被压到过于保守的范围，导致逐图目标先天缺少影调表达。
3. 现已增加 `PT-AESTHETIC-007`：只读取当前照片的可靠蒙版、区域亮度、反差、噪声、黄色/绿色占比及逐图目标，生成 `AdaptiveRegionalTonePlan`。它不读取场景名称，也不复制 R3 参数。
4. 该计划由 `PhotographyDecisionEngine` 生成，经 `PhotoProcessingPipeline` 明确传入 `CoreImageRenderer.renderAutomaticEdit`，并由既有全分辨率区域处理器实际执行；执行回执写入诊断记录。
5. 正式 B 调用保持默认 `adaptiveRegionalTonePlan=nil`；D/E 诊断路径显式传入计划，因此本轮不改变普通拍照成片。
6. `PT-QA-003` 为 M/R3 增加一次有界的“实际失败 → 参数安全修正 → 重新渲染 → 重新质检”。只有质检状态或问题数量真实改善才采用，不更改质检阈值。
7. iOS Build #89 的唯一失败显示当前照片实测黄色/绿色关系仍被全局低置信度过度削弱：黄色饱和调整为 0.0394。修复后，可靠植被蒙版内已经存在的黄色相对绿色优势可提供额外有界增益；仍受饱和度余量和 0.14 上限约束，不是秋季道路预设。
