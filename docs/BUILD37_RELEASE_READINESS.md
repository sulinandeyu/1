## 1. 摄影算法与渲染对应关系

当前实现新增了测量驱动冷调电影目标：阴影和中间调冷色关系、弱暖高光、中性亮部保护及冷暖分离。参数由当前照片亮度、通道关系、可靠区域、噪声和人物证据计算，并进入既有 `AdaptivePhotographyParameterSolver`、`AutomaticEditingRecipe`、`CinematicColorGradingEngine` 和 `CoreImageRenderer`。

正式 B 不启用该模式；只有诊断 D/E 路径显式打开 `enableMeasuredAestheticPlanning`。人物证据存在时，全局电影分级关闭，避免在缺少可靠人物排除蒙版时污染肤色。

但“字段存在并进入渲染器”不等于摄影效果成立。当前只有合成图 Core Image 单项测试和真实照片 Windows 投影；没有当前源码的真实 iPhone 全分辨率成片。

## 2. 秋季道路结论

### A. 已知目标表达能力

Windows R3-W 在已知 T 时能够显著逼近道路暗调、天空压制和冷暖关系，说明参数词汇具有表达潜力。该结果不能证明 Apple Core Image 完全一致，也不能证明自动目标选择正确。

### B. 自动摄影决策能力

不读取 T 的当前自动投影相对旧 D 更冷、更暗，但仍远浅于 T，且没有建立目标所需的道路—植被相对明暗关系。它属于“可见变化”，不属于“冷调电影感已实现”。

## 6. 为什么不能继续叠加规则

当前规则已经能把一张照片变冷、变暗，也能在已知 T 时由反求器找到较强表达；但自主规划在室内、植被和人像上的方向不稳定。现有证据不支持继续添加“如果某测量值则增加某色彩”的规则能够形成通用专业审美。

建议保留确定性 Core Image 渲染器、安全门和人物保护，替换的是“摄影目标生成/排序”层：

1. 输出有限、连续且可解释的目标向量（影调分区、冷暖关系、主体背景关系、中性色/肤色约束），而非场景预设。
2. 用合法的同图多候选人工偏好数据校准轻量目标排序器；候选生成失败与候选选择失败分开标注。
3. 先以现有七张开发/盲测原图做最小闭环，只有出现技术合格且人类偏好的候选后再扩大数据。
4. 模型只决定目标或排序，不生成像素；最终仍由可解释 Core Image 管线执行并经过安全检查。

## 7. 下一步最小动作

工程侧下一步不是上传，而是：在不读取 T 的条件下，通过 iPhone 诊断入口生成当前源码的秋季道路、建筑、阴天植被、室内和人像真实成片。只有真实图先通过 G4，才请求用户进行审美确认。

用户当前无需整理或上传新素材；项目已有素材足够完成下一轮取证。需要用户做的最少操作，是在取得可信的当前版本真机图后，对盲测候选给出“更好 / 都不好 / 差异不明显”的真实选择。
