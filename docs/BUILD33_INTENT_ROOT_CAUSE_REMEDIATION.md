## 同源真实证据

| 候选 | 平均亮度 | 对比跨度 | 阴影占比 | 高光占比 | 平均饱和度 |
|---|---:|---:|---:|---:|---:|
| A 原图 | 0.6313 | 0.8496 | 0.0379 | 0.2615 | 0.1552 |
| B 正式 | 0.5800 | 0.8165 | 0.0524 | 0.2154 | 0.2143 |
| D 自动 | 0.5465 | 0.8451 | 0.0512 | 0.1197 | 0.2250 |
| M/R3-I | 0.5779 | 0.8542 | 0.0485 | 0.2495 | 0.2033 |

D 的地面由 0.6830 降至 0.5198，植被由 0.5527 降至 0.5280；两者只剩约 -0.008 的亮度关系。专业目标/反求证据中的地面相对植被约为 -0.119（线性域），所以 D 并不是“没执行”，而是摄影目标没有建立足够的区域层级。

## 三个独立环节的根因

### 1. 摄影意图生成

旧 `PhotographyTargetProfile.measuredBaseline` 主要围绕原图全局统计建立连续性目标。即使 Vision 给出可靠地面、植被和天空蒙版，旧 `AestheticPhotographyPlanner` 仍缺少“区域之间应该形成什么关系”的目标，只能输出自然纪实、弱色彩分离和接近原图的全局目标。主体不确定性与风险项因此间接主导结果，技术安全被误当成审美选择。

整改 `PT-AESTHETIC-009` 不使用“秋季道路”等场景名称，而只在以下当前照片证据同时存在时提出区域层级假设：

- 地面与植被蒙版均可靠；
- 地面当前亮度高于植被；
- 植被饱和度显著高于地面；
- 两区域覆盖关系足以形成视觉层级；
- 噪声仍有处理余量。

它输出的是 `groundVegetationLuminanceDeltaTarget`、证据强度和 `human-review-required` 状态，而不是固定参数或“审美成功率”。同场景标签但像素关系不同的输入不会得到相同目标。

### 2. 摄影参数求解

旧区域规划器让地面和植被共同追逐一个全局亮度目标，造成地面压暗和植被保护互相抵消。新规划器先由植被自身测量求其连续性目标，再由上述区域关系求地面目标，最后才转换为区域 EV；黄色/绿色关系仍由本图植被统计和饱和度余量求解。

Build 33 旧 D 实际执行：地面 -0.344 EV、植被 +0.013 EV、天空 -0.301 EV。新 Windows 投影所使用的独立求解结果为地面 -0.538 EV、植被 -0.026 EV、黄色饱和 +0.097（旧 D 估算约 +0.082）。投影后地面约 0.489、植被约 0.527，区域关系从 -0.008 增至约 -0.039；RGB MAE 到 T 从 0.2366 降到 0.2248。这证明目标方向和参数链有可测响应，但仍不能证明审美优于 B，也未达到 T 的层级。

另一个尚未关闭的工程差异是测量域：`PhotoAnalyzer` 的亮度来自编码 sRGB，而区域曝光在 Core Image 扩展线性 sRGB 中执行。直接 `log2(target/current)` 不是严格同域映射。当前真实渲染反馈能部分纠正，但只有下一次 Apple/Core Image 渲染测试才能验证目标实际落点；本轮没有用未经验证的换算公式扩大参数。

### 3. 渲染与质量约束

Build 33 `neutralLuminanceLoss` 的逐区归因显示：

| 区域 | 中性色平均亮度变化 | 低于 -0.065 的比例 |
|---|---:|---:|
| 全局旧统计 | -0.1083 | 56.4% |
| 白车/主体代理 | -0.0131 | 4.2% |
| 天空 | -0.0868 | 61.4% |
| 地面 | -0.1784 | 95.4% |
| 植被 | -0.0216 | 9.0% |
| 建筑 | -0.0141 | 3.8% |
| 未分配区域 | -0.0188 | 4.7% |

失败主要发生在被有意压暗的灰色路面，而不是白车、建筑或未编辑中性色。旧检查把两类像素混成一个平均值，导致反馈候选 `failed → failed` 并被拒绝。

`PT-QA-005` 没有关闭检查，也没有放宽原有 -0.065 阈值。它把人物、显著主体和建筑等中性色视为硬保护；明确参与暗调组织的地面等区域单独归因。后者仍必须通过暗部裁切、区域纹理比例和蒙版边界检查，出现真实损伤仍判失败。Build 33 M 的离线重新归因中，受保护中性色变化约 -0.0227，说明旧失败不能单独证明白车或建筑受损；是否在新代码下通过仍须真实 Apple 测试，不能由 Windows 代判。

## 为什么反求能接近 T，而自动 D 不能

反求器直接获得目标 T，因此其目标函数已经包含人类选择的影调、颜色与空间层级；优化器只需寻找能逼近该目标的参数。自动 D 没有 T，必须先判断“哪一种合理目标更值得选择”。旧规则能测量技术问题，却没有可靠的人类摄影偏好监督，所以天然偏向风险最低、最接近原图的目标。

本轮修复了一个有充分像素证据的区域关系和一个错误的质量归因，但它仍是可解释的目标假设，不是通用专业审美模型。若跨场景盲测不能稳定优于 B，继续叠加规则没有依据。替代架构应是：保留现有测量/安全/渲染链，用合法同底片专家对或真实 A/B 偏好数据训练/校准“目标排序器”，由它在若干测量驱动目标之间给出有不确定性的排序；安全检查仍独立，不让排序器修改人物或绕过质量门槛。

## 当前验收结论

1. 已明确分离三层根因，并有 Build 33 真机像素证据支持。
2. 新 D 目标与参数在 Windows 工程投影中产生了有意义的地面/植被层级变化，且未读取 T；T 仅在输出完成后评价。
3. `neutralLuminanceLoss` 已从错误的整图混合平均改为“保护区域 + 有意暗调区域”归因，同时保持原阈值和区域损伤检查。
4. 新 D 尚无 Core Image/iPhone 全分辨率成片，人工摄影审美仍为待验收；不能宣称条件 C 已完成。
5. 除当前同源案例外，现有其他手机素材在 Windows 上缺少与 D 相同的 Vision 蒙版和 Core Image 输出。本轮只有同场景标签不同像素状态的决策测试，跨场景真机回归仍未完成。
6. 正式 B 未变，本轮不提出 Build 34 上传计划。
