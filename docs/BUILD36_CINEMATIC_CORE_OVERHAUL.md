# Build 36 冷调电影感核心整改（2026-11-13）

## 范围与证据边界

- 输入证据：Build 36 真机诊断 ZIP 中同源 A/B/D/E1/E2/M 全分辨率图片与执行 JSON。
- 本地评价参考：已配准秋季道路 T，仅用于求解后的独立评价；不进入自动求解、不打包、不提交 Git。
- 正式 B、普通拍照和保存流程未改变；本轮改动只允许测量驱动 D/E 诊断路径启用。
- Windows 输出是忠实数学投影，不是 Core Image 或 iPhone 验收证据。

## 已确认根因

1. Build 36 的 D/E 白平衡偏移为零，候选差异主要来自道路曝光和曲线；没有独立表达阴影冷、中间调冷、亮部中性保护和暖色重点的目标。
2. 旧颜色分级强度被限制到约 `0.065`，区域色量又在渲染中二次相乘，最终颜色偏移接近不可见。
3. 规则式目标把技术安全和审美方向混在一起：大面积中性色会把风格性颜色关系一并压掉。
4. 全局颜色分级没有可靠人物蒙版排除能力；对人物仅缩弱仍可能污染肤色，因此必须完全关闭。

## 实施

- 新增诊断专用 `measuredCoolCinematic` 分级模式，显式接收阴影冷、中间调冷、弱暖高光、中性亮部保护和冷暖分离目标。
- 使用亮度分区蒙版让冷色主要作用于阴影/中间调，从中间调蒙版中扣除受保护高光；保留 legacy 分支的像素语义。
- 动态求解器只依据当前照片的亮度、通道关系、可靠区域和噪声余量计算目标，不读取 T、文件名、哈希或场景固定预设。
- 人物证据存在时完全关闭全局电影分级；在能够可靠排除人物蒙版前不允许对肤色区域施加该算子。
- 新增 Apple/Core Image 合成像素测试与人物决策保护测试；新增 Windows 投影单元测试。

## 真实图像结果（当前阶段）

- 秋季道路新自动诊断投影相对 A 的 RGB MAE 为 `0.1016`，平均编码亮度由 `0.6313` 降至 `0.5269`；旧 D 的“几乎原图”问题得到可见改善。
- 但新自动投影的线性亮度仍为 `0.3237`，T 为 `0.1861`；道路 `0.2517` 对 T `0.0637`，植被 `0.2514` 对 T `0.1825`。因此它仍明显浅于 T，尚未达到用户目标。
- A/T 反求 R3-W 的区域影调明显更接近 T，证明现有确定性调色词汇具备较强表达能力；这不证明自动目标选择正确。
- 建筑投影形成可见冷灰但未见明显脏青；阴天植被偏暗偏冷；室内出现过强蓝青阴影；人物路径必须关闭全局分级，且仍缺少肤色区域像素级验证。

## 当前结论

- 渲染表达能力：有实质进展，但 Apple/Core Image 合成像素测试尚待远程执行。
- 自主摄影决策：尚未通过。单一显式冷调方向不能安全泛化到室内和人物，规则式目标选择仍缺少人类偏好证据。
- 人工审美状态：`not_evaluated`，不得填写通过。
- 本轮不发布 Build 37，不替换 B。
