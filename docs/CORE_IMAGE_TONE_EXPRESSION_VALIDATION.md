# Core Image 专业影调表达验证

日期：2026-11-09
范围：M / 逆向求解诊断；正式 B、普通拍照与照片保存保持不变。

## 1. 验证问题

秋季街道参数反求表明，当前产品边界 R2 无法充分接近专业目标 T，而研究边界 R3-W 显著缩小了全图和道路区域误差。本阶段只回答两个问题：

1. Core Image 是否能在隔离诊断中表达 R3 所需的全局与区域影调；
2. Windows 模拟与 Apple 实际渲染从哪一阶段开始产生不可忽略的差异。

## 2. 实施内容

- 全局：EV、黑点、七锚点影调、亮度/对比/饱和度、HSL。
- 区域：曝光、高光、阴影、黑点/白点、七锚点中间调、对比、饱和度、HSL。
- 保护：语义蒙版与亮度范围软蒙版相乘；人物存在但缺少可靠整人物蒙版时跳过区域处理。
- 隔离：M 关闭自动区域处理；正式 B/D 继续使用原产品边界和既有处理链。

## 3. 参数边界

研究全局边界：曝光 `-1.2...+0.6 EV`、对比 `0.8...1.35`、黑点 `0...0.10`、白点 `0.70...1`、HSL 色相 `±0.08`、饱和 `±0.35`、明度 `±0.25`。
研究区域边界：曝光 `-1...+0.5 EV`、高光 `0.2...1`、阴影 `0...0.55`、黑点 `0...0.08`、对比 `0.8...1.3`、饱和 `0.7...1.3`，并使用有界七锚点曲线与亮度范围软边。

这些数值仅用于表达能力实验，不是新的产品安全默认值。

## 4. 一致性测试设计

同一组六个 RGB 像素使用 R3 全局参数依次运行：

1. extended-linear-sRGB 工作路径中的 EV；
2. 黑点；
3. 七锚点曲线；
4. `CIColorControls` 与 HSL。

EV、黑点、项目自定义曲线和自定义 HSL 要求紧容差；Apple 未公开内部传递函数的 `CIColorControls` 单列为 Apple 像素基线，不把 Windows 近似写成精确一致。中性区域参数必须逐像素恒等，亮度范围外像素不得被区域处理改变。

## 5. 区域安全证据

每个可靠区域输出：蒙版覆盖率、亮度/颜色/局部对比变化、变化像素比例、源图/成片死黑比例、源图/成片高光比例、细节梯度能量比。原有质量检查继续负责中性色、肤色、噪声、整体细节和蒙版边缘光晕。

## 6. 当前结果

- 远程 iOS Build #76：81 项中 79 项通过；2 个测试方法（3 个断言）失败，Simulator 因测试失败而跳过。
- 失败证据确认旧 Windows 基准在三处不一致：未模拟 32³ 曲线格点插值、在编码 sRGB 而非线性工作域执行 HSL/局部混合、M 使用 0.62 曲线强度而反求器使用 1.0。
- Windows 模拟已改为 32 格点插值、线性工作域 HSL/区域混合，并将 R3 M 明确设为 `.dramatic`；Python 单元测试 4/4 通过。
- 完整模拟感知 HSL 立方体后重新反求的 R3-W：全图 RGB MAE `0.0652`，道路亮度 `0.0686`（目标 `0.0638`），道路减植被亮度关系 `-0.1400`（目标 `-0.1191`）。
- 远程 iOS Build #77（run `42579545332`）：81 项中 80 项通过；EV、黑点、32³ 曲线和区域亮度保护均通过，只剩 `CIColorControls + HSL` 与 Windows 近似最大偏差 `59/255`。Apple 实际基线为 `[[0,0,0],[3,14,32],[114,0,0],[58,44,0],[13,32,0],[76,76,76]]`；该私有阶段已从“跨平台一致性”中隔离，自定义 HSL 另行紧容差测试。
- 远程 iOS Build #78（run `42580580448`）：HSL 单独测试最大偏差 `31/255`，证明旧模拟还遗漏 Swift 内部的 encoded-sRGB 感知转换与 HSL 立方体插值；反求器已按源码补齐并生成 R3 v3，下一次 Apple 运行将验证修正结果并采集新版私有滤镜基线。
- 远程 iOS Build #79（run `42582348554`）：81 项像素/决策测试全部通过；App 完整编译发现质量检查闭包的可选返回类型推断错误，随后修复。
- 远程 iOS Build #80（run `42583561947`）：81 项测试全部通过；App 完整编译发现 `PhotographyRegionImpact` 新安全字段缺少可供 App 目标使用的显式初始化器，随后补齐并保留旧调用的默认值。
- 远程 iOS Build #81（run `42584431183`）：81 项测试全部通过；采集到当前 R3 v3 的 Apple 私有颜色控制基线 `[[0,0,51],[21,41,55],[132,57,0],[128,103,0],[0,2,0],[112,112,112]]`。临时 `18/255` 容差已替换为该实测基线的 `3/255` 回归容差；同时修复诊断探针预览闭包缺少显式返回值的 App 编译错误。
- 远程 iOS Build #82（run `42585880410`，HEAD `03ce99a5`）：81/81 测试通过、0 失败，iOS Simulator App 构建成功。EV、黑点、32³ 曲线、自定义 HSL、区域中性恒等、亮度范围保护以及原有场景/人物保护回归均通过。
- Windows 静态 diff：通过。
- 修正后 Core Image 合成像素阶段：Build #82 通过。Apple 私有滤镜只承诺 Apple 基线回归，不宣称与 Windows 近似数学精确一致。
- iOS Simulator 编译：Build #82 通过。
- R3-I 秋季街道全分辨率样片：尚未生成。
- 人工视觉验收：待 R3-I 产生后进行。

因此当前结论是“表达代码已接入诊断路径，Apple 合成像素与 App 编译通过；私有秋季原图的 R3-I 和人工视觉尚未验收”，不是“已达到 T”。
