# 小苏相机 V8 iPhone 验收计划

## 当前实际发布路径

开发电脑无需安装 Xcode。项目沿用既有流程：

`Windows 本地修改` → `提交并推送 main` → `GitHub Actions / iOS Build（macos-latest）` → `GitHub Actions / TestFlight Release` → `App Store Connect 处理` → `iPhone TestFlight 安装`

其中推送和触发 TestFlight 都属于外部状态变更，必须得到用户明确确认后才能执行。没有推送前只能写“本地代码已准备”，不能写“已生成可安装版本”。

## 构建级别必须分开记录

- 代码已实现
- Swift 自动测试通过
- Xcode/iOS Simulator 构建通过
- iPhone 端到端处理通过
- 真实视觉质量人工验收通过

前一项不能替代后一项。

## 必测素材

黄土峡谷与蓝天、逆光环境人像、晴天城市、阴天风景、室内暖光、城市夜景、日落、已经具有良好画质的原图。每类至少一张苹果相机原始文件，禁止微信压缩和截图替代。

## 操作步骤

1. 在 Windows 确认只提交 V8 文件，保留用户其他未跟踪资料。
2. 推送后等待 `iOS Build` 在 GitHub 的 macOS runner 上依次完成 `swift test` 和 iOS Simulator Debug build。
3. 构建通过后手动触发既有 `TestFlight Release` workflow；等待 Archive、IPA 导出和上传全部成功。
4. 等待 App Store Connect 完成处理，在 iPhone TestFlight 中安装新构建，记录提交号、构建号、机型和 iOS 版本。
5. 对每张原图执行一次小苏相机自动处理。
6. 保存原图、V7 成片、V8 成片以及“摄影问题诊断”“AI 摄影决策”“像素与处理链诊断”完整截图。
7. 记录三个候选的状态、分数、区域变化、选择原因、候选耗时和总耗时。
8. 连续处理至少 5 张照片，检查内存、卡顿、崩溃和结果串图。

## 推荐测试顺序

第一张先测 `TestPhotos/original.jpg` 对应的蓝天与黄土峡谷原始照片，因为项目已有旧版成片和参考图，最容易判断 V8 是否保护天空、改善山体层次，以及候选选择是否真实优于旧版。确认流程和诊断截图完整后，再按环境人像、普通风景、室内、夜景的顺序测试。

## 通过标准

- 明显问题照片至少有一个候选改善主要问题，且最终选择理由与测量一致。
- 优质原图允许克制变化，不因差异阈值被强制处理。
- 蒙版方向、尺寸和覆盖正确，没有明显光晕或颜色泄漏。
- 夜景不被提亮成白天；室内暖光不被错误中和；天空不过蓝。
- 原图与成片分别保存，预览与相册文件一致。
- 人物脸型、五官、肤色关系、皮肤纹理、头发和身体比例保持真实。
- 候选预算超时时明确记录 `skipped`，不得静默跳过。

每组提供原始文件、V7/V8 成片、三页诊断截图、机型、iOS、构建号、处理耗时、是否修正、最明显改善和最明显问题。
