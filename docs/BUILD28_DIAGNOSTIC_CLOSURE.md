## 3. 已确认根因

1. `AestheticPhotographyPlanner` 旧逻辑只在“混合光 + 高亮源”下生成颜色分离目标。Build 28 已有植被黄色 `50.9%`、绿色 `19.2%`，但 `colorSeparation=0`，区域证据只写入说明，没有成为目标。
2. D 的黄色 HSL 只由区域饱和度余量乘以保守系数得到 `+0.0195`；审美规划没有实质控制 HSL，导致 D 和 B 配方接近。
3. D 只执行一次“计划→渲染→质检”，没有用渲染后实际像素重新测量目标差距。日志中的目标达成 `62%` 不能推动第二次有界修正。
4. Build 28 的 D 目标亮度沿用通用中灰中心 `0.419`，源图实测为 `0.637`，但曝光又被安全范围限制为约 `-0.039 EV`。目标与可执行幅度不协调，并且日志没有并列输出同定义的首轮/最终测量。
5. C 状态是 `unavailable/indexUnavailable`，但导出器按名称前缀回退，抓到了旧的低分辨率 C 预览并写成 `C_reference_candidate.jpg`。这是状态—图片绑定错误，不是 C 真正执行。

## 4. 实际代码整改

- `PhotographyTargetProfile.measuredBaseline`：D 改为当前照片源图相对目标；亮度目标由可恢复高光/阴影、纯白/纯黑压力和噪声余量计算，并与复测共用 `PhotoAnalyzer` 定义。B 不变。
- `AestheticPhotographyPlanner`：可靠植被区域内的黄色/绿色共存、主色关系和饱和度余量可以形成有上限的颜色协调目标；不推断物体身份，不按“秋季道路”调用参数。
- `AdaptivePhotographyParameterSolver`：黄色 HSL 读取区域颜色协调强度；饱和度/明度继续受原区域余量约束。
- `PhotoProcessingPipeline`：D 最多执行一次“完整分辨率渲染→同定义复测→有界残差修正→重新渲染→重新质检”。只有技术状态不失败且目标达成有实质提高才采用第二次结果；B 不运行该闭环。
- `ManualPhotographyParameters.rendererVerification`：M v3 降低反差、黑点、天空压暗和 HSL 幅度，仍保持可感知表达；只用于诊断，尚未在 iPhone 证明通过。
- `DiagnosticBundleExporter`：候选必须是同一记录的 `executed` 状态且精确匹配 `imageStageName` 才导出；`unavailable` C 只输出 `C_UNAVAILABLE.txt`。
- M 诊断详情新增实际反差、中性色覆盖/亮度偏移、触发阈值及区域影响，避免下一次仍只能从 issue 名称猜测。
