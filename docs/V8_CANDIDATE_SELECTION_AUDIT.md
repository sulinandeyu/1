# V8 候选选择审计

日期：2026-10-26

## 三个候选是否只是固定滤镜

三个候选都从当前照片的摄影决策配方派生，不是三个 LUT：

- 自然保守：降低全局/局部强度并关闭颗粒等风险效果。
- 层次增强：在平淡或空间深度不足时提高曲线、中间调分离和局部对比。
- 问题定向：按欠曝、高光、阴影、偏色、噪声及区域问题逐项修改。

但它们共享同一基础配方，因此当照片问题没有覆盖真正主体时，差异确实可能只剩强度变化。柿子树案例暴露的正是“主体没有进入问题与评分”的缺口。

## 已修复的错误目标

V8 build 22 之前已经修复“零变化也获得 50% 改善分”的错误。本轮进一步修复：普通显著主体不再只写进计划，而会产生区域统计、局部处理回执和候选区域变化；当主体区域存在欠曝或层次不足时，它会成为 `PhotoProblemReport` 的区域问题，并进入候选问题改善分。

`QualityCheckService` 现在也把 `.subject` 视为必须有真实执行回执的局部处理。空计划、无效蒙版或幅度不足不能再被登记为主体精修成功。

## 当前评分边界

- 技术失败候选不能凭高改善分获胜。
- 未测得正确方向变化时改善分为 0。
- 缺失主体区域指标时不能获得主体改善分。
- 像素差异仍不是单一目标；高光、色偏、噪声、人物完整性和蒙版边缘仍是硬质量门。
- 是否“更美”仍需人工偏好校准，代码不会把分数直接宣称为审美真理。

## 人工偏好记录机制

三个候选将显示在现有逐阶段诊断预览。人工比较后使用：

```powershell
.\scripts\Record-PhotographyPreference.ps1 `
  -CaseId V8-PERSIMMON-01 `
  -Choice B `
  -Build 23 `
  -PhotoSha256 <原图SHA256> `
  -Reason "层次增强候选的果实与叶片分离更自然，天空未偏色" `
  -ProblemSummary "自动结果主体仍偏弱"
```

候选映射固定为：`A=自然保守`、`B=层次增强`、`C=问题定向`。另外允许 `none`（三个都不好）和 `original`（原图更好）。脚本要求理由和原图 SHA-256，并把记录标记为 `human-confirmed`；没有真实选择时不会生成偏好数据。
