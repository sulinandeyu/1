# 小苏相机 V9 逐图智能摄影后期引擎

## 结论

V9 不再把场景标签直接映射成一套固定强度。场景、人物与区域语义仍用于判断摄影意图和安全边界，但曝光、高光、阴影、反差、曲线、白平衡、饱和度、细节与亮度蒙版的核心执行值，改由当前照片的像素测量独立求得。

本轮修改建立的是可执行配方与证据的一一对应关系，不是提示词或只供展示的参数 JSON。`AutomaticEditingRecipe` 仍是 Core Image 渲染器的真实输入。

## 已确认的旧问题

1. `PhotographyCandidatePlanner` 曾将整份配方乘以 0.76、0.94、1.0 等统一强度，白平衡、HSL、曝光和风格参数一起缩放。三个候选本质上仍容易成为同一方向的强弱版本。
2. `RegionalPixelAdjustment.make` 虽读取区域统计，但主体、地面、植被、建筑等仍使用 0.43、0.38、0.34、0.40 等固定绝对亮度目标。不同照片中的同一区域容易趋向相似结果。
3. 诊断页能显示最终配方，却没有对每个关键参数同时给出输入测量、摄影目标、允许范围和实际执行值，难以判断是识别错、方案错还是渲染未执行。
4. 场景代码中已有较多颜色风格分支；即使后续做了安全限制，仍可能让语义标签对颜色的影响大于当前照片的真实色彩证据。

## Build 22 三类故障的区分

| 层级 | 已有证据 | V9 处理 |
| --- | --- | --- |
| 识别/主体 | Build 22 诊断识别到 `outdoor/sky/cloudy/plant`，但曾把整图摄影风格偏向建筑；通用显著性只能证明视觉区域，不能证明“柿子”身份 | 保留 V8.1 Scene Profile 权重修复；主体不可靠时明确进入整图协调，不伪造对象身份；增加蒙版技术质量证据 |
| 方案 | Build 22 柿子冠层的改善很弱，候选仍是整份配方的强度缩放，区域使用固定绝对亮度目标 | 新增逐图参数规划器、动态候选轴与相对全图的区域目标 |
| 渲染/评分/保存 | Build 22 诊断记录 RGB MAE、变化像素、执行模块和区域回执，说明不是简单返回原图；但像素变化并未解决主体问题，天空反而变暗增色 | 评分继续以问题改善、主体、区域协调、保真和肤色/中性色风险为主；新增最终参数执行结果，把“已传值”和“产生了什么像素结果”分开记录 |

因此本轮没有把问题笼统归因于“参数太保守”，也没有修改拍照、保存或 UI 主链。已证实的主要根因位于参数规划、候选派生和区域目标，而不是最终 JPEG 被原图覆盖。

## V9 实现

### 1. 权威逐图参数规划器

`PerPhotoParameterPlanner.refine` 在旧场景语言之后运行，覆盖关键技术参数，防止早期场景默认值再次主导最终配方。它分别使用：

- 全图平均亮度、中间调占比、空间亮度方差；
- 高光、纯白、阴影和纯黑占比；
- 5%–95% 亮度跨度与空间层次；
- RGB 通道差、混合光风险与已诊断色偏；
- 平均饱和度、细节分数和噪声代理；
- 天空、植被、主体等可靠区域的实际统计。

夜景使用更低的自然亮度中心，不会被归一化成白天。没有确认色偏时，色温和色调修正为零；阴天天空不允许凭标签自动增加蓝色。

### 2. 参数证据链

`PhotographyParameterEvidence` 为以下参数记录摄影目的、输入证据、目标、允许范围、实际值、预期结果和降级行为：

- 曝光、高光、阴影；
- 对比度、色调曲线、白点与黑点；
- 色温、色调；
- 饱和度、自然饱和度；
- 局部对比度；
- 降噪、锐化；
- 亮度蒙版强度。
- 橙色、绿色与蓝色 HSL 的区域测量依据。

这些证据会进入运行日志和诊断页。候选被选中或质检修正配方后，实际值随最终 `AutomaticEditingRecipe` 刷新。完整分辨率渲染后，`ImageProcessingDiagnostics` 还会记录每个参数对应的源图/成片亮度、高光、阴影、动态范围、RGB、饱和度、噪声/细节或区域影响结果，明确区分“计划值”和“像素执行结果”。

### 3. 动态候选而非统一强度候选

三个候选仍保留现有接口名称，但用途已改变：

- 自然保守：保留逐图技术修正，只削弱可选风格和在噪声风险下限制纹理；
- 层次增强：只在实测反差或空间层次不足时调整曲线、局部对比和主体分离；
- 问题定向：只增强问题检测器确认的曝光、高光、暗部、噪声或局部问题。

候选之间不再统一缩放白平衡、HSL 和整份配方。

### 4. 相对区域目标

主体、地面、植被、水面和建筑的目标亮度改为相对当前照片全局亮度与区域反差求值。区域阴影恢复同时受纯黑占比和噪声余量限制。区域原因文本会记录区域亮度、全图参考与本次目标。

`NormalizedPhotoMask.qualityAssessment` 现在记录覆盖率、软边比例、边界密度和可靠度。空蒙版、尺寸错误、接近全图的宽蒙版会被拒绝；高碎片边界会降低可靠度并出现在诊断回执中。该指标只判断蒙版的技术可用性，不伪装成语义识别正确性证明。人物与显著主体排除仍是独立硬保护。

### 5. 色彩和人物保护

- HSL 从中性状态开始，只在可靠区域统计存在时计算有限调整；
- 橙色调整需要可靠非人物主体证据，人物照片的橙色色相、饱和度和明度调整保持为零；
- 人物继续禁止磨皮、美白、瘦脸、几何修改、面部重建和生成式处理；
- 阴天、人物、中性色与肤色仍受 V8.2 的源图相对质量检查保护。
