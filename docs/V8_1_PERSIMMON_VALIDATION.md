## V8.1 预期诊断

1. Scene Profile 应显示户外、阴天、植被主导、自然纪实倾向；建筑权重应明显低于植被/纪实权重。
2. 最终风格不得再是 `urbanArchitecture`。
3. 主体置信度不得再直接等于场景识别最高置信度。
4. 若主体蒙版可靠，应出现“显著主体：已执行”，并显示实际曝光、对比、饱和度、清晰度和覆盖率。
5. 若主体蒙版不可靠，应明确显示“整图协调”，不得伪造主体处理成功。
6. 候选页应记录三个候选的问题改善、主体改善、区域协调和保真分。

## 肉眼验收重点

- 橙色果实存在感和通透度提升，但不过饱和；
- 树叶层次更清楚，不发灰、不发荧光；
- 石板路略有空间引导感；
- 阴天天空保持自然灰白，不产生青蓝污染；
- 房屋、器材和电线杆不被强化成主体；
- 不出现 HDR 光晕、白边、脏色、过锐或明显蒙版边界。

## iPhone 操作步骤

1. 等代码提交并推送后，使用现有 `TestFlight Release` 工作流生成新构建，建议下一个唯一构建号为 23。
2. 安装新构建后，从应用的诊断样片入口重新导入同一张 `original.jpg`；不要使用 Build 22 成片作为输入。
3. 保存原图和 AI 成片，不通过微信二次压缩后再作为像素基准。
4. 截取 Scene Profile、主体/区域执行、三个候选评分、质量检查与差异页。
5. 在阶段预览中保存主体蒙版、主体叠加、仅全局、全局+局部以及三个候选。
6. 将新成片、上述截图和人工偏好（A/B/C/都不好/原图更好）提供回来。
