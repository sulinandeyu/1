# 小苏相机专业摄影参数逆向求解实验

日期：2026-11-09  
状态：Windows 隔离研发完成；未修改正式 B、拍照或保存；未执行 Core Image/iPhone 验收；未上传 Build 31。

## 1. 结论先行

秋季街道 A/T 已证明为同一画面，但 T 相对 A 存在约 1.5% 缩放与最多约 53 px 裁移。反求实验不是把 T 混入 A，而是只用 A 经过声明的曝光、影调、HSL 和蒙版参数生成 R。

结果分成两个层次：

1. **当前 App 参数边界内**：R 已明显不同于原图，能够压暗道路、提高秋叶/环境分离；加入局部处理后全图 RGB MAE 从 `0.1268` 降到 `0.1104`。但道路线性亮度仍为 `0.2003`，目标为 `0.0638`，视觉上仍明显偏亮，因此实验 A 对“当前产品边界足以逼近目标”的假设判定为**失败**。
2. **扩展边界缺口探针**：不改变变换种类，只临时放开隔离实验范围后，全图 RGB MAE 降到 `0.0694`，道路亮度达到 `0.0685`，接近目标 `0.0638`。这说明主要根因是当前全局/区域参数范围和区域影调表达不足，而不是现有参数名称完全无法表达该方向。该图不是当前 iOS 能力，不可进入正式算法。

最重要的实际图片是：[A/T/R 对比图](../output/inverse_solver/autumn_street/A_T_R_comparison.jpg)。顺序为 A 原图、T 配准目标、R1 当前边界全局、R2 当前边界全局+局部、R3 扩展边界缺口探针。

## 4. 可运行程序与数学边界

程序：[inverse_solver.py](../PhotographyInverseSolver/inverse_solver.py)；运行说明：[README.md](../PhotographyInverseSolver/README.md)。

程序忠实复刻 Swift 源码中公开可见的部分：

- 扩展线性 sRGB 工作值、sRGB 输入输出转换。
- EV 倍率、黑点多项式。
- `CinematicToneMappingEngine` 七锚点、smoothstep 和单调约束。
- `ProfessionalHSLProcessor` 的编码域 HSV、色相软权重与色度保护。
- 现有语义蒙版羽化、区域曝光/对比/饱和度和 alpha 合成顺序。

Apple 没有公开 `CIColorControls`、`CIHighlightShadowAdjust`、`CITemperatureAndTint`、`CIToneCurve` 的完整内部传递函数。Windows 实验把高光/阴影、白平衡和五点曲线保持中性，只对 `CIColorControls` 做语义近似。因此不能把 Windows R 宣称为 Core Image 真机成片；迁移任何值之前必须增加 Apple 环境像素一致性测试。

## 5. 当前边界反求参数

全局主要参数：曝光 `-0.350 EV`、亮度 `-0.0363`、对比 `1.1143`、黑点 `0.0335`、低中间调 `-0.080`、中间调 `-0.080`、饱和 `1.080`、黄色 Hue `-0.025`、黄色亮度 `+0.080`。

局部主要参数：地面曝光 `-0.140 EV`、对比 `1.075`；植被曝光 `+0.140 EV`；天空曝光 `+0.0796 EV`；建筑曝光 `-0.140 EV`。

至少 19 个控制落在或非常接近当前上下限，包括全局曝光、低中间调、中间调、饱和、黄色 Hue/亮度、地面曝光/对比、植被曝光、天空曝光、建筑曝光。这是当前边界不足的直接证据，不是“优化器没有调整”。完整数值见 [inverse_result.json](../output/inverse_solver/autumn_street/inverse_result.json)。

## 6. 全局与局部改善

| 结果 | 全图 RGB MAE | 全图线性亮度 MAE |
|---|---:|---:|
| R1 仅全局 | 0.1268 | 0.0908 |
| R2 全局+现有局部 | 0.1104 | 0.0798 |
| R3 扩展边界缺口探针 | 0.0694 | 0.0511 |

局部处理对现有边界有真实贡献（RGB 误差降低约 12.9%），主要来自地面/道路压暗以及植被相对恢复；不是只改变 JSON。但当前地面局部曝光最小只有 -0.14 EV，远不足以建立目标中的道路暗调。

## 8. 真实渲染缺口

现有 `RegionalPixelAdjustment` 对地面/植被/建筑只暴露曝光、高光、阴影、对比、饱和度、温度和清晰度；没有区域黑点、区域白点、区域分段曲线或区域 HSL。当前负向区域曝光又被限制到约 -0.14 EV。目标采用明显压暗整体/道路、同时以 +89 阴影保留暗部细节的组合，单一的轻微局部曝光无法复现。

工程措施应先验证：

1. 在 M/诊断路径增加**测量驱动且安全受限**的区域中间调或区域曲线能力，而不是扩大所有正式照片的统一强度。
2. 对道路/背景压暗与阴影细节保护分开控制，避免以单纯 -1 EV 制造死黑。
3. 在 Apple 环境建立 Python/Swift 同一小图的曝光、黑点、七段曲线、HSL、蒙版混合逐阶段像素对照。
4. 通过技术质检与人工盲测后，才讨论自动规划如何预测这种目标；反求值不得写成“秋季道路预设”。
