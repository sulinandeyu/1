# 摄影参考数据与现有引擎对接

## 已检查的生产链

当前生产链继续使用：

`PhotoAnalyzer` → `PhotoProblemDetector` → `PhotographyDecisionEngine` / `AdaptivePhotographyParameterSolver` → `PhotographyCandidatePlanner` → `CoreImageRenderer` / `LocalAdjustmentProcessor` → `QualityCheckService` → `PhotoProcessingPipeline`。

本轮不修改拍照、原图保存、Core Image 渲染或成片保存逻辑，也不新增平行摄影引擎。

## 对接边界

1. `PhotoAnalyzer` 的当前照片测量值转换为与数据集一致的查询向量。
2. 只在授权与内容风险允许的 `reference` 记录中，按连续测量值检索近邻；不按 `portrait`、`landscape` 等名称直接取参数。
3. 近邻只提供“合理目标分布”的证据，例如亮度分位范围、饱和度范围、中性色漂移边界、中心/外围层次关系；不复制某张图的滤镜或滑块。
4. `AdaptivePhotographyTargetGenerator` 将参考分布与当前照片的问题、噪声风险、人物保护、场景氛围约束共同求解。
5. `AdaptivePhotographyParameterSolver` 仍输出逐图参数证据；每项必须记录当前测量、目标、边界、实际值、规则 ID 和作用区域。
6. 候选必须由现有 Core Image 管线真实渲染。`QualityCheckService` 先做技术安全门控，摄影问题改善和人工偏好单独计分。

## 推荐查询向量（不含场景固定模板）

- 亮度：P05/P25/P50/P75/P95、阴影占比、高光占比、黑白端点占比。
- 色彩：RGB 均值、平均饱和度、12 段色相分布、冷暖比例、中性色覆盖与中性色 RGB。
- 细节：梯度能量、网格局部对比均值/离散度。
- 构图代理：中心与边缘亮度/饱和度/细节差。没有可靠主体蒙版时必须标记为代理值，不能称为主体测量。
- 可靠局部区域：仅使用 Vision/分割生成并通过覆盖率、边缘和置信度检查的区域统计。

所有维度先按参考集稳健分位数标准化；缺失值不以零伪造，使用显式缺失掩码。

## 目标求解约束

- 距离权重由摄影问题相关性决定。例如高光溢出只提高亮度尾部分位的权重，不应把“天空”标签变成蓝色增益。
- 人物照片使用原图相对肤色与纹理保护，参考库不得把他人肤色当作中性色目标。
- 参考目标只作为软约束。高光、暗部噪声、混合光和色彩空间完整性等安全规则优先。
- 没有足够近邻或授权状态不足时，降级到现有实测驱动求解器，并记录 `reference_lookup_unavailable`。

## 候选评价

- 技术层：高光/黑位、偏色、中性色、肤色、噪声、锐化、蒙版边界、画布和保存一致性。
- 问题改善层：原始问题是否按正确方向改善。
- 参考一致性层：仅比较目标统计区间，不以像素相似或类别相同作为美学成功。
- 人工偏好层：保留 A/B/C/原图/都不好评价；未收集的数据不得标为用户偏好。

## 未接入原因

本轮只建立合规数据与实测特征。参考库尚无摄影师调整意图标签，也没有完成 iPhone Core Image 渲染/人工偏好校准，因此不把参考距离写入生产评分，避免未经验证的数据改变正式出片。满足许可复核、至少 30 张隔离验证、真实渲染和人工偏好四项后，再以可关闭的实验开关接入。
