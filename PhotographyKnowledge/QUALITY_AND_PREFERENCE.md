# 质量评价与人工偏好

## PT-QA-001：技术安全与审美偏好分层

- 来源：PAPER-IQA-01、PAPER-IQA-02。
- 问题：像素变化率只能证明发生变化，不能证明更美；技术指标也不能完全代表审美。
- 方法：第一层检查裁切、死黑、色偏、噪声、过锐、蒙版边界和人物保护；第二层检查原始摄影问题是否改善；第三层保留 A/B/C/原图/都不好的人工作品偏好。
- 不适用：没有人工标注时不得把自动得分称为真实用户偏好。
- 副作用：只奖励低风险会永远选择最弱候选；只奖励变化会制造夸张效果。
- 验证：记录候选参数、技术分、问题改善分与人工选择，分开统计。

## PT-QA-002：质量回退必须可解释

- 方法：回退需记录触发指标、阈值、被拒候选和最终文件标识；禁止静默返回原图并显示成功。
- 验证：诊断页和日志能从最终文件追溯到实际参数、渲染与质量结论。

## PT-QA-003：强影调的结果反馈安全修正

- 来源：`PT-QA-001/002`、`ADOBE-TONE-01/02`、`ADOBE-MASK-01`；Build 31 M/R3-I 的真实质检失败证据。
- 解决问题：强影调验证可以接近摄影目标，但全局压暗与全范围局部压暗叠加后造成暗部裁切、中性色亮度损失和蒙版边界伪影。
- 输入测量：`QualityCheckService` 的 `tooHarsh`、阴影/黑位异常、中性色亮度与色度偏移、区域边界问题及真实区域影响；不得由预设名称触发。
- 适用条件：仅 M/R3 隔离诊断；第一次真实 Core Image 渲染和质检均已完成，并存在可修正的明确问题。
- 不适用条件：渲染失败、质检没有可修正证据，或修正候选没有减少问题/改善状态。
- 计算方法：保持原始强影调意图，但有界收回全局反差和中间调压缩，按实测中性色损失恢复有限曝光；把局部调整限制到中间亮度范围、增加羽化、减少区域 EV/曲线幅度并对暗部增加保护。重新真实渲染和质检；不修改任何质检阈值，只有状态或问题数量改善时才采用。
- 副作用：修正可能降低与目标图的数值拟合度，或仍不足以消除复杂蒙版产生的伪影。
- 验证：保留修正前后完整参数、图片和质检；检查地面/建筑黑位、白车和中性色、天空端点、蒙版边缘及人工观感。Windows 参数测试不能替代 Core Image/iPhone 验收。

## PT-QA-004：参数生命周期审计

- 来源：`PT-QA-001/002` 与 Build 27–32 诊断中“计划存在但实际变化过弱”的执行证据。
- 解决问题：求解参数在可靠性、安全、颜色、人物保护或产品边界阶段被覆盖后，诊断只显示最终值，无法定位损失发生在哪一层。
- 输入测量：求解器输出及每个限幅阶段前后的同一 `AutomaticEditingRecipe`。
- 适用条件：B/D/E 的决策与诊断；生命周期只记录，不产生新参数。
- 不适用条件：不得把记录中的计划值冒充渲染值。
- 计算方法：依次记录 `solverOutput → analysisReliabilityLimits → problemSafetyLimits → colorIntegrityGuards → portraitProtection → finalProductBounds`，只列真实变化字段；最终渲染和渲染后测量仍分别记录。
- 副作用：诊断 JSON 增大，但不增加图像处理时间。
- 验证：自动测试确认阶段顺序和最终配方；诊断 ZIP 能区分 planned、limited、rendered、measured。

## PT-PREF-001：隔离样本上的人工摄影偏好校准

- 来源：`PAPER-IQA-01/02`、`PT-QA-001`，以及 Build 27–33 中“技术通过但人工观感未通过”的真实项目证据。
- 解决问题：工程代理分数只能衡量目标达成、保真和已知风险，不能证明候选具有专业摄影审美；最接近原图也不能天然获胜。
- 输入测量：同源原图与两个真实渲染候选的哈希、技术质检状态、摄影目标、实际参数、盲化左右位置、人工选择、问题标签和评价者。开发集与盲测集必须按原图哈希隔离。
- 适用条件：候选已完成真实像素渲染且来源可追溯；只有技术安全候选可进入正式排序器训练，但技术失败候选仍可作为负例保留。
- 不适用条件：没有人工选择、只有自动得分、不同原图冒充前后对照、许可不清或把参考目标参数写回自动 D。
- 方法：技术层先排除不可接受损伤；偏好层只在技术允许的候选间学习成对选择或输出不确定。低置信度必须弃权，不能回退为“最接近原图就是最美”。
- 副作用：样本不足时排序器无法覆盖全部摄影意图，评价者偏好也可能分歧；因此需要按原图分组划分、重复评价和不确定性校准。
- 验证：使用 `PhoneValidationDataset/cross_scene_split.json` 的独立盲测集，至少记录 B/D 或两个目标候选的双盲选择；分别报告技术通过率、目标合理率、人工胜率和一致性。Windows 统计、Swift 测试或像素变化率不能替代真实人类偏好。

## PT-PREF-002：候选生成失败与候选选择失败分离

- 来源：`PT-PREF-001`、`PT-QA-001`，以及 Build 29–33 中“多个技术通过候选仍可能都不好看”的真实项目证据。
- 解决问题：把“没有一个值得选择的候选”和“存在好候选但排序器没有选中”分成两个可追踪问题，防止把生成器缺陷错误归因于缺少排序训练数据。
- 输入测量：同源 D/E1/E2 的真实 Core Image 输出、每个候选的技术状态、实际参数与区域变化、盲化人工选择、当前自动选择结果。所有输入按原图 SHA-256 归组。
- 适用条件：三个候选均由当前照片测量独立求解并完成真实渲染；技术失败候选保留诊断但不能进入最佳成片选择。
- 不适用条件：缺少任何真实候选、Windows 模拟图、旧版本单候选、没有人工评价却把工程代理分数当作“好候选”。这些情况只能标记证据不完整或偏好待评价。
- 方法：若全部候选技术失败，记录 `candidateGenerationFailedTechnical`；若技术可用候选全部被人工判为不好，记录 `candidateGenerationFailedHumanReview`；若至少一张获人工支持而自动选择未命中，记录 `candidateSelectionFailed`；没有人工标签时保持 `preferencePending`。
- 副作用：在完成小样本人工评价前，系统会更频繁地报告“未知”，但这比伪造审美成功更可靠。
- 验证：Swift 契约测试覆盖缺图、全技术失败、全人工拒绝和选错好候选；诊断 ZIP 输出 `candidate_generation_and_selection.json`；跨场景盲测页面逐图记录真实选择且允许“都不好”。
