# 专业摄影参数逆向求解

本页约束“已知同源原图与专业目标图时，验证现有渲染器表达能力”的研发实验。它不是正式相机的目标生成器，也不允许在用户没有目标图时检索案例并复制参数。

## PT-INVERSE-001：同源配准与有效区域门控

- **来源**：`ADOBE-TONE-01/02` 的非破坏编辑前提；本项目秋季街道 A/T 实证。
- **解决问题**：区分真正的影调/颜色变化与缩放、裁剪、不同帧、水印、压缩差异。
- **输入测量**：尺寸、SHA-256、SIFT 对应点、RANSAC 单应矩阵、内点率、重投影误差、有效重叠范围。
- **适用条件**：内点率至少 85%，中位重投影误差不超过 1 像素，并经视觉核对为同一画面。
- **不适用条件**：不同时间、视角、视频帧、物体位置或光线状态；此时不得建立前后配对。
- **方法**：只在配准后的有效重叠区域计算损失；发布平台水印、黑边和无对应像素排除出目标函数，但不从交付照片中生成式删除。
- **副作用**：单应配准不能校正明显景深视差、运动物体和滚动快门形变。
- **验证**：保存配准矩阵、内点统计、有效区域蒙版和 A/T 叠加检查。

## PT-INVERSE-002：渲染器约束的分阶段反求

- **来源**：`APPLE-CI-01/02`，以及项目 `CoreImageRenderer`、`CinematicToneMappingEngine`、`ProfessionalHSLProcessor` 的真实数学定义。
- **解决问题**：判断曝光、影调、HSL 和可靠局部蒙版是否足以表达已知专业目标。
- **输入测量**：当前 A 像素、配准 T、现有参数范围、工作色彩空间、处理顺序、语义/亮度蒙版。
- **适用条件**：`PT-INVERSE-001` 通过，且目标图仅作本地研发验证。
- **不适用条件**：把 Lightroom/iPhone 滑块直接当 Core Image 数值；把 T 像素混合、覆盖到 R；把反求参数写成场景模板。
- **方法**：先在低分辨率拟合全局参数，再在全分辨率验证；第二阶段才加入已有可靠蒙版。目标函数同时约束 RGB、线性亮度、区域关系和参数复杂度。多个近似解优先选择更简单、稳定、少伪影的组合。
- **副作用**：Apple 未公开的滤镜内部传递函数无法在 Windows 完全复刻；任何参数迁移前必须执行 Core Image 像素一致性测试。
- **验证**：交付 A/T/R、参数 JSON、区域误差、边界变化、上下限命中情况；Windows 结果明确标记为模拟而非 iPhone 成片。

## PT-INVERSE-003：表达能力与安全范围分离

- **来源**：`PT-QA-001`、`PT-INVERSE-002`。
- **解决问题**：分清“变换类型做不到”和“当前安全上限太窄”两类根因。
- **输入测量**：当前约束反求结果、撞限参数、扩展边界缺口探针、技术风险指标。
- **适用条件**：当前边界解在多个关键参数上撞限且目标误差仍明显。
- **不适用条件**：把扩展边界结果直接作为生产安全参数，或以拟合误差替代摄影审美验收。
- **方法**：扩展边界只在隔离 Windows 实验中运行；若同一变换词汇的误差显著下降，则记录需要新增的参数表达或重新校准的边界，之后在 Apple 环境、技术质检和人工盲测中单独验证。
- **副作用**：扩展结果可能出现裁切、光晕、噪声或中性色损伤，不能进入 B/D 正式链路。
- **验证**：报告当前边界与扩展边界的全图/区域误差、参数、细节与裁切指标，人工评价状态保持 `pending`。

## 当前案例结论边界

秋季街道 A/T 是同一画面，但 T 有约 1.5% 缩放与裁移。当前 App 边界可以建立明显的道路/树冠关系，却无法把道路压到目标亮度；隔离扩展边界能显著缩小该差距。这证明“现有变换词汇有部分表达能力、当前范围与局部控制不足”，不证明正式相机已经学会自主选择该目标。
