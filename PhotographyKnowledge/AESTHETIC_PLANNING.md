# 逐图视觉理解与摄影审美规划

本文件记录“视觉证据如何成为摄影目标”，不是风格预设表。场景标签只能描述意图和风险，不能直接绑定 LUT、曲线、HSL 或固定参数。

## PT-UNDERSTANDING-001：语义证据边界

- 来源：`APPLE-VISION-01/02`、本项目内置 DETR panoptic 模型的模型说明与 Apache-2.0 元数据。
- 解决问题：区分场景分类、类级语义蒙版、人物蒙版与通用显著性，避免把颜色块或显著区域写成确定对象身份。
- 输入测量：Vision 场景标签/置信度、人脸、人物蒙版、显著性蒙版、Core ML 类级语义蒙版、覆盖率、边界密度、区域影调/色彩统计。
- 适用条件：对应 API/模型真实执行，且蒙版质量与置信度达到门槛。
- 不适用条件：模型失败、空蒙版、覆盖过宽/过窄、边界碎片化、类别不在模型能力内。
- 计算方法：生成 `VisualSceneUnderstandingResult`；可靠证据进入主体候选，低置信度内容写入 `unknowns`；通用显著性只称为视觉显著区域。当天空、地面、植被、建筑等可靠环境蒙版合计覆盖超过 52% 时，小于 20% 的非人物/动物/食物类级区域不能单独证明摄影主体，系统进入整图与区域关系协调；阈值依据后续真机样本继续校准。
- 副作用：保守门控会漏掉真实主体；类级语义分割不能区分多个同类实例。
- 验证：诊断记录必须包含来源、覆盖率、置信度和未知项；真机核对蒙版叠加图，不得仅看标签名。

## PT-AESTHETIC-001：实测视觉层级

- 来源：`ADOBE-TONE-01/02`、`ADOBE-MASK-01`、`TUTORIAL-LOCAL-01`（未授权本地教程，仅作研究需求提炼）。
- 解决问题：主体、背景及空间引导元素之间没有清楚但自然的明暗层次。
- 输入测量：主体/背景亮度差、全局与区域反差、显著性、语义蒙版可靠度、道路/地面覆盖、噪声、高光/阴影风险。
- 适用条件：主体或结构区域证据可靠；否则进入整图协调模式。
- 不适用条件：无法定位主体、人物蒙版不可靠、暗部噪声过高或端点已经剪切。
- 计算方法：以原图关系为起点，只求解需要修正的残差；主体偏暗时小幅缩小负亮度差，主体已经足够突出时不继续加强；局部反差受噪声余量限制。
- 副作用：过强分离会产生假 HDR、光晕或舞台式人物提亮。
- 验证：A/B/C 同图对比、区域像素统计、蒙版边缘检查和人工盲测；人物需额外验证源图相对肤色与纹理。

## PT-AESTHETIC-002：区域颜色协调

- 来源：`ADOBE-MASK-01`、`ADOBE-PS-01`、`APPLE-CI-01/02`、`TUTORIAL-LOCAL-01`。
- 解决问题：全局统一调色导致肤色、白色、天空或植被同时偏色。
- 输入测量：可靠中性色、全图及区域 RGB/饱和度/亮度、区域内实测黄色与绿色像素比例、混合光、人物/皮肤保护、光源位置和区域蒙版。
- 适用条件：存在可靠区域统计和颜色调整余量。
- 不适用条件：没有可靠蒙版、中性色不足、混合光无法解释或人物保护风险过高。
- 计算方法：保留现场色彩关系。冷暖分级仍要求混合光与可靠空间证据；但可靠区域内同时存在的主次颜色关系可独立形成有上限的颜色分离目标。HSL 由当前区域饱和度/亮度残差、黄色/绿色比例及中性色保护共同求值，不复制参考图参数。黄色比例只是颜色证据，不等于树叶、果实或任何物体身份；无可靠区域、颜色证据低、区域已饱和或人物保护风险高时调整保持为零。
- 副作用：区域蒙版边缘可能出现色带；全局 HSL 可能误伤相似颜色。
- 验证：中性色染色、肤色偏移、区域颜色变化、蒙版边缘和人工自然度评价；同一内容的低饱和/高饱和输入应产生方向正确且不同的黄色 HSL 结果。

## PT-AESTHETIC-003：摄影氛围保护

- 来源：`ADOBE-TONE-01/02`、`PAPER-CC-01/02/03`、`TUTORIAL-LOCAL-01`。
- 解决问题：技术校正把夜景、暖光、阴天、雾气或真实光源校成统一中性外观。
- 输入测量：整体亮度、混合光、高亮源、空间亮度方差、可靠中性色、场景分类置信度和当前色彩关系。
- 适用条件：存在可测量的现场光/时间氛围证据。
- 不适用条件：只有低置信度场景标签或单一全图 RGB 均值。
- 计算方法：把氛围作为参数上限和保护权重，而不是参数来源；不能恢复的剪切细节不伪造，阴天不自动加蓝，暖光不盲目中和。
- 副作用：保护过强会让调整显得保守；保护过弱会产生统一滤镜感。
- 验证：同场景不同曝光/白平衡的参数方向测试、真实 iPhone 成片和人工偏好记录。

## PT-AESTHETIC-004：渲染—复测有限反馈

- 来源：`ADOBE-TONE-01/02`、`ADOBE-MASK-01`、`APPLE-CI-01/02`、`PT-QA-001`。
- 解决问题：一次性参数预估与实际像素结果不一致，导致目标存在但渲染变化过弱，或局部调整被颜色空间、处理顺序和蒙版混合削弱。
- 输入测量：源图 `PhotoAnalyzer` 指标、摄影目标范围、首轮完整分辨率渲染后使用同一分析定义得到的亮度/反差/饱和度、区域影响及技术质检。
- 适用条件：仅隔离 D 诊断；首轮真实渲染与复测均成功，存在超过容差且可安全修正的残差。
- 不适用条件：首轮渲染失败、人物/中性色保护风险、反馈候选质检失败、目标达成没有实质改善或已达到一次迭代上限。
- 计算方法：最多增加一次有界修正；只根据同定义的目标残差微调曝光、亮度、反差、自然饱和度及可靠区域色彩，不改变场景类别，不调用 LUT/预设；反馈候选必须重新渲染、重新测量、重新质检，只有技术状态不恶化且目标达成提高时才采用。
- 副作用：增加一次完整分辨率渲染的时间与内存峰值；自动技术目标仍不能替代人工摄影审美。
- 验证：日志记录源图、首轮、最终同定义测量值、反馈次数、选用原因和实际最终配方；远程 Core Image 测试后仍须 iPhone A/B/D 盲测。

## PT-AESTHETIC-005：逐图摄影目标假设

- 来源：`ADOBE-TONE-01/02`、`ADOBE-MASK-01`、`PT-AESTHETIC-001/002/003`。
- 解决问题：单一且保守的目标即使达到率很高，也可能没有足够的影调组织或颜色重点。
- 输入测量：源图亮度、反差、阴影/黑位、高光/白位、噪声、氛围保护、可靠区域蒙版覆盖、区域亮度/反差、区域内黄色/绿色比例及饱和余量。
- 适用条件：仅隔离诊断导入；源图分析完成，至少全图技术测量可靠。语义区域不足时只允许使用全图端点和亮度关系。
- 不适用条件：分析或渲染失败、人物/中性色保护证据不足以支持更强调整、目标要求生成原图不存在的内容。
- 计算方法：从同一源图分别求解“空间层次”和“克制暗调”等目标假设；名称只描述优化目标，不提供固定参数。每个目标的亮度、反差、局部反差和颜色分离均由当前图残差独立计算，并经同一求解器和 Core Image 链执行。
- 副作用：增加诊断渲染时间和内存；多个技术可行目标未必能自动判断哪一个更美。
- 验证：同源 A/B/D/E1/E2/M、独立参数证据、区域复测、技术质检和人工盲测；正式 B 不受影响。

## PT-AESTHETIC-006：技术、目标与人工审美三层评价

- 来源：`PAPER-IQA-01/02`、`PT-QA-001`。
- 解决问题：把“无技术异常”或“目标达成率高”错误写成“审美成功”。
- 输入测量：技术质量状态、摄影目标及其证据置信度、目标达成率、区域影响、人工盲测选择和问题标签。
- 适用条件：任何诊断候选评价。
- 不适用条件：没有真实渲染图片时不得产生人工审美结论；没有人工选择时只能记录 `awaiting_blind_review`。
- 计算方法：分别记录 `technicalQualityStatus`、`targetQualityStatus`、`humanAestheticStatus`。自动评分最多说明技术可行性和既定目标残差，不自动选出审美赢家。
- 副作用：系统会更频繁地报告“不确定”，但避免虚假的高审美成功率。
- 验证：ZIP 状态与实际图片一一对应，盲测结果可追溯到同源候选；像素变化率不参与“最美”判定。

## PT-AESTHETIC-007：实测驱动的增强区域影调

- 来源：`ADOBE-TONE-01/02`、`ADOBE-MASK-01`、`APPLE-CI-01/02`、`PT-AESTHETIC-001/002/004`；Build 31 真机 A/B/D/M 同源诊断用于失败校准，不作为固定参数来源。
- 解决问题：D 已能识别地面、植被、天空和建筑，但只执行极弱的局部参数；M 证明渲染器具有强影调表达能力，却因全亮度范围叠加和端点无保护造成死黑、中性色损失与蒙版边界风险。
- 输入测量：当前照片全局亮度/反差/黑白端点/噪声，可靠区域蒙版及其覆盖率，区域亮度/反差/阴影/高光/饱和度，区域内黄色与绿色比例，以及逐图摄影目标和规划置信度。
- 适用条件：仅隔离 D/E 诊断路径；区域蒙版有效、质量可用且覆盖率不低于 0.4%；人物出现但人物蒙版不可靠时停用增强区域计划。
- 不适用条件：空蒙版、碎片或过宽蒙版、区域统计缺失、人物保护证据不足、调整方向无法由当前像素残差证明。
- 计算方法：不读取场景名称。由区域实测值和逐图目标求区域 EV、阴影/高光保护、七段曲线残差与 HSL；地面、植被、建筑限定中间亮度范围并使用至少 0.16 的羽化，天空只在高亮范围内恢复层次且不凭空加蓝。所有参数作为 `AdaptiveRegionalTonePlan` 直接进入正式 Core Image 全分辨率区域处理器，并把执行回执与复测结果写入诊断。
- 副作用：自动区域调整与原有轻量区域处理叠加会增加渲染时间；蒙版不准确时仍可能产生局部反差或颜色边界；过度保守则审美表达不足。
- 验证：Build 31 同源证据记录 D 与原图 RGB MAE 约 3.85%，而 M/R3-I 约 28.21%；新实现需通过动态参数方向测试、真实 Core Image 像素测试、区域暗部/高光/中性色/边界质检及 iPhone 人工盲测。技术通过仍不得写成审美通过。

## PT-AESTHETIC-008：区域渲染响应反馈

- 来源：`ADOBE-TONE-01/02`、`ADOBE-MASK-01`、`APPLE-CI-01/02`、`PT-AESTHETIC-004/007`；Build 31/32 的 D 与 M/R3-I 同源真机证据仅用于失败校准。
- 解决问题：可靠区域的动态曝光、曲线或 HSL 已进入渲染器，但实际区域像素响应远小于计划；或强响应只在局部产生暗部裁切、中性色损失和蒙版边界风险。
- 输入测量：首轮全分辨率渲染的区域亮度/颜色/局部对比变化、区域暗部和高光比例、细节能量、技术质检问题，以及首轮实际区域参数。
- 适用条件：仅隔离 D/E 诊断；首轮 Core Image 渲染、区域复测和质检均完成；区域蒙版仍可靠。
- 不适用条件：人物保护不足、渲染或复测失败、区域没有计划调整，或第二轮技术质检失败。
- 计算方法：最多一次反馈。安全且响应不足时只沿原计划方向有限提高区域曝光/中间调或现有颜色分离；出现区域暗部、端点、中性色或边界风险时只收回受影响区域并提高亮度范围保护和羽化。重新从原图渲染并复测；不把第一轮结果叠加到第二轮，也不改变质量阈值。
- 副作用：增加一次全分辨率渲染；响应达成仍不代表审美成功，增强幅度仍需真机盲测。
- 验证：记录首轮/反馈轮的区域执行达成、参数、区域影响和质检；方向测试覆盖响应不足与风险衰减；最终以同源 D 图像和人工评价验收。
